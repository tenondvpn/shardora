# M6 子分片广播：详细实现方案

> 本文档是 `UNIFIED_FORMAL_PROOF.md` 第三部分机制 M6 的工程展开，覆盖架构设计、中继选举、广播流程、覆盖率分析与安全性。本版本基于 N=10^5 候选节点、现有子分片 P2P 网络拓扑（J=1，k_pool=1024，P=100）。无 BLS 聚合逻辑。

---

## 一、问题：1024 个委员会如何向 10 万节点广播块

委员会（k=1024）生成 QC 块后，需将块广播到全部 N=10^5 候选节点。直接 Gossip 需要 $O(\log N) \approx 17$ 跳、$O(N)$ 条消息。

**M6 方案**：委员会从每个子分片中随机选取 1 个中继节点，共 R=P=100 个中继，每个中继将块广播到其所属的单一子分片（现有确定性 P2P 拓扑）。

```
R=P=100 中继节点，每节点属于 J=1 个子分片
100 中继节点 × 1 子分片/节点 = 100 次子分片内广播
P=100 个子分片全部覆盖（每子分片恰好 1 个中继）
每个子分片 ~1024 个成员，接收后在子分片内 Gossip
```

**零新基础设施**：子分片 P2P 拓扑和 JoinElectTx 容量控制均已实现。

---

## 二、整体架构

```
委员会（k=1024）生成 QC 块
      │
      ▼
为每个子分片 p=0..P-1 各选 1 个中继：
  r_p = FisherYates(M_p, 1, epoch_random_ XOR p)
  其中 M_p = {i ∈ C_T : pool_id_i = p}（子分片 p 的候选节点集）
      │
      ▼ （委员会向 R=P=100 个中继节点单播块）
中继节点 r_0, r_1, ..., r_99
  每个 r_p 属于唯一子分片 p：
    pool_id_{r_p} = H(node_id_{r_p}) mod P
      │
      ▼ （每中继节点广播到所属子分片，共 100 条子分片广播）
子分片 pool_0, pool_1, ..., pool_99
  各子分片 ~1024 成员通过子分片内 P2P Gossip 接收块
      │
      ▼
全部 N=10^5 候选节点接收到 QC 块
```

## 三、中继节点选举

### 3.1 子分片分配（已有实现）

每个候选节点属于唯一一个子分片，由节点 ID 哈希确定：

```
pool_id_i = H(node_id_i) mod P
```

- `P = ⌈N/k_pool⌉ = ⌈100,000/1024⌉ ≈ 100`（子分片数）
- `k_pool = 1024`（每子分片容量上限，由 JoinElectTx 共识强制）
- 每节点 J=1，仅属于一个子分片

### 3.2 中继选举算法

```
for p in 0..P-1:
    M_p = {i ∈ C_T : pool_id_i = p}   // 子分片 p 的候选节点
    r_p = FisherYates(M_p, 1, epoch_random_ XOR uint64(p))  // 选 1 个中继
relay_set = {r_0, r_1, ..., r_{P-1}}   // R=P=100 个中继
```

- `epoch_random_`：时间块 BLS 门限签名哈希（已有 `vss_manager.cc:18`）
- `p`：子分片编号，作为 seed 修改量，保证每子分片的中继选举相互独立
- 覆盖率：**确定性 100%**（每子分片恰好有 1 个中继，P 个子分片全覆盖）

### 3.3 中继节点被动发现

中继节点无需"感知"自己是中继——委员会直接向 relay_set 成员发送块，relay_set 成员收到块后自然向所属子分片 Gossip（走现有块同步路径，`key_value_sync.cc`）。

## 四、广播流程

### 4.1 委员会侧

```
1. 生成 QC 块（已有共识路径）
2. 计算 relay_set：为每子分片 p 选 1 个中继
   relay_set = {FisherYates(M_p, 1, epoch_random_ XOR p) : p=0..P-1}
3. 向 relay_set 中的 R=100 个节点单播块（100 条 P2P 消息）
```

### 4.2 中继节点侧

```
1. 收到委员会发来的块
2. 验证块合法性（已有 EnqueueVerifyBlock 路径）
3. 向所属唯一子分片内广播块（走现有子分片内 Gossip）
   pool_id_self = H(node_id_self) mod P
```

### 4.3 普通候选节点

```
1. 通过子分片内 Gossip 收到块（现有路径）
2. 验证块（已有）
3. 正常参与候选池等待下一轮选举
```

## 五、覆盖率分析

### 5.1 确定性 100% 覆盖

M6 为每个子分片 p=0..P-1 独立选 1 个中继：

- **每子分片有且仅有 1 个中继**
- P=100 个子分片全部覆盖
- 覆盖率 = 100%（确定性，不依赖概率/哈希均匀性假设）

这与 R=100 随机选取中继（覆盖率约 64%）的方案根本不同：**M6 的中继集合按子分片分层选举**，而非全局随机抽取。

### 5.2 拜占庭中继的影响

若子分片 p 的中继节点 $r_p$ 是拜占庭节点，拒绝转发块：

- 影响范围：仅 1 个子分片（~1024 个节点暂时未收到块）
- **兜底机制**：该子分片节点通过 pull 同步（已有 `key_value_sync.cc`）在下一出块间隔内追上
- 最坏情况（$\beta=1/3$ 拜占庭）：约 33 个子分片需要 pull 同步，其余 67 个子分片通过中继实时收到块

### 5.3 参数对比

| 方案 | 中继数 R | 覆盖率 | 说明 |
|-----|---------|-------|------|
| 全局随机选 R=100 | 100 | ~64%（概率） | M6 旧方案，依赖哈希均匀性 |
| **每子分片选 1 个（M6 最终方案）** | **P=100** | **100%（确定性）** | 分层选举，全覆盖保证 |
| 全局随机选 R=500 | 500 | ~99.8%（概率） | 对比参考 |

**M6 最终方案以 R=100 条单播实现确定性 100% 覆盖，优于任何全局随机方案。**

## 六、与现有系统的集成

### 6.1 代码改动范围

```
核心共识路径（hotstuff.cc 投票/QC/提交）：零改动

key_value_sync.cc：中继节点收块后触发子分片内广播（现有路径，零改动或小改）
```

### 6.2 与 M2 的信标复用

```
epoch_random_ = Hash(QC.sign_x ‖ QC.sign_y)   [已有 vss_manager.cc:18]

M2 用法：committee = FisherYates(all_members, epoch_random_)
M6 用法：relay_p   = FisherYates(M_p, 1, epoch_random_ XOR p)  // 每子分片独立
```

### 6.3 时序

```
[委员会生成 QC 块]
    │
    ▼ 同步
[为每子分片选 1 中继（本地，O(P)=O(100)）]
    │
    ▼ 并行
[向 R=100 个中继节点单播块]
    │
    ▼ 中继节点收到后
[子分片内广播]→ 全网节点在 2-3 跳内收到块
```

## 七、安全性分析

### 7.1 中继节点拒绝转发

**攻击**：被选为中继的拜占庭节点拒绝转发块，导致其覆盖的子分片未收到块。

**影响**：R=100 中若有 $b$ 个拜占庭中继，丢失 $b$ 个子分片。当 $b < P/3 \approx 33$ 时（BFT 假设 $\beta < 1/3$），仍有 67+ 个诚实中继覆盖其子分片。

**兜底**：未收到块的子分片通过 pull 同步（现有 `key_value_sync.cc`）在下一出块间隔内追上。

### 7.2 中继节点传递错误块

**攻击**：拜占庭中继节点传递篡改的块。

**防御**：所有候选节点收块后执行 `EnqueueVerifyBlock()` 验证 QC 签名（已有），无效块被丢弃。中继节点无法伪造委员会 BLS 门限签名。

### 7.3 中继节点预测与定向攻击

`relay_set` 由 `epoch_random_ XOR p` 确定，`epoch_random_` 在时间块 QC 产生时才固化（M2 暴露窗口压缩机制）。攻击者在 QC 产生前无法预测各子分片的中继节点。

## 八、参数汇总

| 参数 | 值 | 说明 |
|------|---|------|
| $N$（候选节点数） | $10^5$ | 系统目标规模 |
| $J$（每节点子分片数） | 1 | 确定性哈希分配，已有实现 |
| $k_{\mathrm{pool}}$（子分片容量） | 1024 | JoinElectTx 强制上限，已有实现 |
| $P$（子分片总数） | $\lceil N/k_{\mathrm{pool}}\rceil = 100$ | 由 N 和 k_pool 决定 |
| $R$（中继数） | $P=100$ | 每子分片 1 个中继，R=P |
| 覆盖率 | 100%（确定性） | 分层选举保证全覆盖 |
| 委员会单播数/块 | 100 | 相比直接 Gossip 节省 $N/R=1000\times$ |

**最终推荐**：R=P=100，每子分片选 1 中继，确定性全覆盖，零 BLS 聚合逻辑。
