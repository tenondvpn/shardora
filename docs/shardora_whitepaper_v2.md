## 摘要

Shardora 是一个高性能、真去中心化的公链系统，通过**二维并行分片**在保持拜占庭容错安全性的前提下实现近线性水平扩展。系统在单分片内同时运行 32 个并行执行池，最大支持 1024 个分片，理论峰值吞吐量超过 **1000 万 TPS**，当前 4 分片实测吞吐 **40,000 TPS**，单交易最终性延迟约 **1 秒**。

Shardora 融合了改进的 Fast-HotStuff BFT 共识、BLS 门限签名（O(1) 聚合验证）、基于 Feldman VSS 的三阶段分布式密钥生成、阿贝尔群无锁跨分片资产转移协议，以及 EVM 全兼容的智能合约执行环境。系统独创 Feistel 双射地址派生机制，从数学层面杜绝跨分片伪造增发攻击，是全球首个在工程层面完整实现执行分片的公链系统。

本白皮书详述 Shardora 的系统架构、密码学基础、共识协议、经济模型与工程实现，面向开发者、验证者及学术研究者。

## 1. 引言与背景

### 1.1 区块链不可能三角

自比特币诞生以来，公链系统长期面临**不可能三角**的根本制约：去中心化、安全性与可扩展性三者难以同时兼顾。比特币以极高的去中心化和安全性换来了约 7 TPS 的严重不足；以太坊 2.0 尝试分片扩展，最终承认执行分片"工程上极难实现"而转向 L2 Rollup；Solana 追求高 TPS 的代价是节点门槛极高，去中心化存疑；Polkadot 的平行链架构跨链延迟高，安全共享机制复杂。

现有分片方案面临三类核心挑战：

- **跨分片原子性**：多分片事务难以在无信任环境下实现原子提交
- **委员会换届停机**：DKG 需要数百秒，换届期间服务中断
- **性能与安全权衡**：委员会越大越安全但越慢，BFT 消息复杂度随节点规模平方增长

### 1.2 Ethereum 2.0 执行分片的七年困局

![ETH2 困境与 Shardora 突破](fig7_eth2_vs_shardora.jpg)

*图1：Ethereum 2.0 执行分片七年演变路线与 Shardora 逐一攻破对照*

以太坊是全球投入最多资源探索执行分片的公链项目，其失败轨迹提供了最有价值的反面教材。

**2018 年**：以太坊提出宏大分片路线图，目标 1024 个执行分片，宣称是"不可能三角的完美解法"。**2020 年**：执行分片数从 1024 缩减至 64，信标链上线但跨分片合约执行问题悬而未决。**2021 年**：Vitalik Buterin 宣布转向"以 Rollup 为中心"的路线图——本质是官方承认执行分片在工程上难以实现。**2022–2023 年**：EIP-4844 仅引入数据分片，执行分片被永久放弃。**2024 年至今**：完整 Danksharding 持续延期，以太坊实际依靠中心化 Sequencer 承接执行层。

ETH 2.0 执行分片的五大根本困境：

| 困境 | 以太坊结局 | Shardora 解法 |
|------|-----------|--------------|
| 跨分片合约原子执行 | 放弃：需多轮消息传递 | 阿贝尔群 + CrossShardBase，已实现 |
| 委员会换届停机 | 未解：DKG 200 秒，TPS 归零 | 等待分片并行预 DKG，零停机 |
| 单维分片扩展天花板 | 接受：每分片单池执行 | 二维：1024 分片 × 32 池 |
| 同步跨分片消息 | 未解：收据机制多跳 >10 秒 | GBP 异步聚合，最终一致 |
| 跨分片桥接安全性 | 失败：Harmony Bridge 被盗 $1 亿 | Feistel 双射 + BFT 阈值 |

L2 Rollup 方案同样存在根本局限：Arbitrum 由单一 Sequencer 排序，去中心化程度极低；Optimistic Rollup 的欺诈证明挑战窗口导致 L1 最终性需要 7 天；不同 L2 之间的原子操作至今无标准方案。Shardora 在 **L1 层**直接解决了这些问题。

## 2. 系统架构

![系统架构总览](fig1_architecture.jpg)

*图3：Shardora 三层网络拓扑、二维并行分片与等待分片换届机制*

### 2.1 三层网络拓扑

**通用网络**：基于 Kademlia DHT 的覆盖网络，承担全节点发现、路由和 TCP/UDP 混合传输。

**根国会**（Root Congress，网络 ID = 2）：全局委员会选举执行层，负责分片创建与销毁、Epoch 时间块同步及 VSS 可验证随机数生成。

**共识分片**（ID 3–1026，最大 1024 个）：每分片运行独立的 Fast-HotStuff BFT 共识，包含 32 个并行执行池。每分片对应一个**等待分片**，存放下届候选委员会，在当届运行期间并行预执行 DKG，保证换届零停机。

### 2.2 二维并行分片

Shardora 的扩展性来源于两个正交并行维度：

**维度一：分片间并行**——最多 1024 个独立分片同时处理交易，分片间通过 GBP 协议异步传递跨分片消息，总吞吐量随分片数线性增长。

**维度二：分片内池级并行**——每分片内 32 个执行池独立并发处理，交易按发起地址哈希取模路由到固定池，池间无状态依赖，零竞争冲突。

**总吞吐量公式**：Total TPS = 分片数(N) × 32 × 每池吞吐(T) → 随 N 线性扩展，无固有上限。

### 2.3 关键系统参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 最大共识分片数 | 1024 | 链上治理自动扩容 |
| 每分片并行执行池 | 32 | 池内独立 BFT 共识 |
| 每分片最大委员会规模 | 1024 节点 | BFT 门限 t = ⌈2n/3⌉ |
| Epoch 周期 | 600 秒 | 约 10 分钟 |
| DKG 总时长 | ~200 秒 | 三阶段，后台并行 |
| 当前在线分片 | 4+1 | 4 共识分片 + 根国会 |

## 3. 共识协议：Fast-HotStuff BFT

![共识流程与 DKG 换届](fig6_consensus_dkg.jpg)

*图4：Fast-HotStuff 两阶段流水线、BLS 签名聚合、DKG 三阶段与零停机换届时序*

### 3.1 协议设计

Shardora 共识基于 **Fast-HotStuff** 改进型 BFT 协议。安全门限 t = ⌈2n/3⌉，容忍 f < n/3 个拜占庭节点。每个分片内 32 个执行池各自独立运行一个 Fast-HotStuff 实例，32 条流水线并发推进，互不干扰。

### 3.2 两阶段流水线提交

Fast-HotStuff 的核心优化是**两阶段流水线**：每个区块携带前一区块的法定人数证书（QC），Block(h+1) 到达时立即触发 Block(h) 的不可逆提交，无需独立的 Commit 轮次。相比原始 HotStuff 三阶段，最终性延迟降低约 33%，单分片区块确认时间稳定在 1 秒以内。

### 3.3 增强视图同步（EVS）

标准 HotStuff 视图切换需要 O(n) 条广播消息，在千人委员会中引入可观延迟。EVS 改进方案要求副本节点**仅接受携带当前视图有效 QC 的消息**才推进视图，将视图切换从广播驱动变为 QC 驱动，通信复杂度降至常数级。实测在 1024 副本规模下，视图切换延迟 < 500ms，单分片端到端确认 < 2 秒。

### 3.4 法定人数证书（QC）结构

每个 QC 包含视图编号、被认证区块哈希、密钥版本号（elect_height）以及 BLS 聚合签名的两个 G1 坐标分量。其中 elect_height 是连接选举、DKG 和共识的核心索引，防止旧签名被重放攻击者用于认证新区块。

### 3.5 双花防护

系统在 BFT 提案阶段对每个地址的交易序号（Nonce）实施单调性校验。任何提案中如有地址的 Nonce 不连续或重复，整个提案在投票阶段即被拒绝，双花请求在最终提交前完全被淘汰。

## 4. BLS 门限签名系统

### 4.1 密码学基础

Shardora 使用 **alt_bn128（BN254）椭圆曲线**上的 BLS 签名。曲线分为两个群：G1 为签名空间，G2 为公钥空间；通过双线性配对函数连接两者，满足 e(a·P, Q) = e(P, a·Q) = e(P, Q)^a 的核心性质，使得聚合签名的单次配对验证成为可能。

### 4.2 门限签名聚合

每个副本节点用自己的私钥份额对区块哈希签名，产生部分签名。领导者收集 t = ⌈2n/3⌉ 个部分签名后，通过 Lagrange 插值重建聚合签名，最终仅需一次双线性配对即可验证，验证复杂度 O(1)，与委员会规模完全无关。

**核心优势**：1024 节点委员会的全轮次共识结果可压缩为 96 字节聚合签名，这是 Shardora 支持超大委员会的密码学基石。

### 4.3 防密钥替换攻击

系统同时使用聚合 BLS（AggBLS）对节点身份进行持有证明（Proof of Possession）。若无此机制，攻击者可构造特殊公钥使其与若干诚实节点公钥之和为零，从而伪造"聚合签名"。双重 BLS 方案在签名层面彻底消除此类攻击。

## 5. 分布式密钥生成（DKG）

### 5.1 协议基础

DKG 基于 **Feldman 可验证秘密共享**，整个过程约 200 秒，分三阶段完成。参与条件要求至少 80% 的节点成功完成密钥交换，否则 DKG 失败并触发重试。

### 5.2 三阶段协议

**阶段一（0–80 秒）：Feldman 承诺广播**

每个节点随机生成 t 阶多项式，并向全网广播该多项式系数在 G2 空间的承诺向量。这些承诺向量用于后续阶段的份额合法性验证，一旦广播即不可抵赖。

**阶段二（80–160 秒）：加密秘密份额交换**

每个节点对其余每个节点分别计算多项式取值，使用目标节点的 ECDH 公钥加密后点对点发送。接收方解密后用阶段一的承诺向量独立验证份额合法性，将不合法份额的发送节点标记为失信。

**阶段三（160–200 秒）：本地聚合与公告**

每个节点在本地聚合所有诚实节点发来的份额，得到自己的私钥份额；同时聚合所有节点的常数项承诺，得到公共公钥，并向全网广播完成状态。

### 5.3 零停机换届机制

**等待分片机制**是解决换届停机问题的核心工程创新。下届候选委员会在当届 Epoch 运行期间驻留于等待分片，在后台独立完成三阶段 DKG（约 200 秒）。换届时刻新委员会密钥已完全就绪，切换瞬间无任何停机窗口，业务层 TPS 无损失。

此外，对于大部分节点连任的场景，系统通过密钥复用优化仅为新加入成员增量更新密钥份额，换届同步开销降低约 90%。

## 6. 委员会选举：FTS 算法

### 6.1 选举流程

每个 Epoch（600 秒）由根国会执行，使用**适应度比例选择（FTS）**加权随机算法选出下届委员会。任何节点提交加入选举交易（携带 BLS 验证向量、质押量、公钥和地理区域信息）后即可参与下轮选举，无白名单，无准入许可。

选举随机种子来自 VSS 可验证随机函数，而非链上可预测的区块哈希，防止攻击者提前布局 Sybil 节点定向入选特定分片。

### 6.2 四维权重复合

节点的 FTS 综合得分为四个维度的乘积：

**质押权重（PoS）**：质押量越高，被选中概率越大，形成经济安全激励。数值经 2/3 分位平滑并加入随机扰动，防止头部节点绝对垄断。

**信用权重**：基于历史出块率、在线时长和投票参与度计算，历史表现越优异的节点被选中概率越高，激励长期诚实行为。

**区域权重**：基于节点 IP 地理位置评估区域多样性。同一地理区域节点密度过高时，该区域节点权重受罚，强制促进委员会地理分散化，提升系统对地区性网络故障的抗性。

**任期权重（反向）**：连续在任 Epoch 数越长，权重越低。这一反向设计防止委员会成员长期固化，保持成员流动性和系统活力。

### 6.3 淘汰与增补

每轮淘汰底部 10% 的节点，其中参与度过低者直接淘汰，其余通过反向 FTS 随机淘汰。新节点增补规则：委员会规模低于 256 人时可翻倍增长（快速扩张期）；超过 256 人后每轮增长 5%（稳定期）。

## 7. 跨分片通信：GBP 协议

### 7.1 设计目标

**群广播协议（GBP）**解决分片区块链中跨分片通信的消息爆炸问题。其核心思想是将本分片在某一高度区间内发往目标分片的所有跨分片消息聚合为单条转账交易，消息压缩比约 **6,000 倍**，从 O(S²×P) 降至 O(S²)（S 为分片数，P 为每分片池数）。

### 7.2 消息生命周期

跨分片转账首先在源分片经过 Fast-HotStuff 两阶段提交确认；GBP 在确认后将该高度内所有发往目标分片的消息聚合为一条 kNormalTo 交易；该聚合交易本身也需在源分片经历一次完整共识提交；目标分片验证高度连续性后按序处理，缺口触发主动同步补全。

### 7.3 三层重放保护

GBP 消息通过三个独立机制防止重放攻击：

- **唯一哈希锚定**：每条消息绑定到特定区块的 BLS 聚合签名，不同 Epoch 的签名产生不同哈希，历史消息无法复用
- **数据库存在性检查**：持久化记录所有已处理消息的唯一哈希，节点重启后仍有效
- **高度单调性约束**：目标分片强制按源分片出块顺序处理聚合消息，拒绝任何乱序到达

### 7.4 因果序保证

对于相关联的跨分片事务，系统提供严格的**因果顺序**保证：若源分片中事务 A 先于事务 B 提交，则在目标分片中 A 的效果也严格先于 B 的效果出现。这种保证由 GBP 的高度批处理约束和双轮共识机制共同提供，无需全局锁或分布式协调器。

## 8. 跨分片资产转移协议

![跨分片资产转移协议](fig3_cross_shard.jpg)

*图5：四层架构、Feistel 双射地址派生、GBP 消息聚合与零铸造安全模型*

### 8.1 四层架构

Shardora 跨分片资产转移协议采用四层分离设计：

**价值层**：基于阿贝尔群可交换性的资产转移，满足强最终一致性（SEC），无锁无协调器。

**控制层**：幂等全量覆盖的状态同步，通过 LWW（最后写入者获胜）版本栅栏防止陈旧状态覆盖。

**计算层**：AMM 等复杂计算逻辑 100% 封闭在单分片执行池内，非可交换算子不跨越分片边界，保证复杂操作的原子性。

**宿主执行层**：C++ EVM Host 实现编译期常量 Gas 定价，配合事务快照栈（HostJournalStack）提供子调用失败时的无损回滚能力。

### 8.2 阿贝尔群无锁转账

代币余额更新为整数加法，满足**交换律**：对同一余额 B 先后施加增量 Δ₁ 和 Δ₂ 的结果，与施加顺序无关，最终均等于 B + Δ₁ + Δ₂。

这一数学性质的直接推论是：无需分布式锁，跨分片消息即使乱序到达，最终状态仍正确收敛。这彻底消除了两阶段提交（2PC）死锁与回滚级联问题，是 Shardora 实现高吞吐跨分片转账的数学基础。

### 8.3 Feistel 双射地址派生

为防止跨分片合约身份伪造，系统引入 **160-bit Feistel 置换网络**，将合约的"本体地址"与其在各分片的"分身地址"之间建立可验证的双射关系。

置换网络采用 4 轮 Feistel 密码结构，每轮轮密钥由分片编号、池编号和轮次编号通过哈希确定性生成。当分片编号和池编号均为零时，映射退化为恒等变换，与以太坊地址格式完全兼容。

系统在共识层对每条跨分片消息强制验证：目标地址的逆映射必须等于源地址的逆映射。违反此断言的消息在共识阶段直接被拒绝，任何试图伪造合法跨分片合约身份的攻击在协议层面被彻底封堵。

### 8.4 零铸造分身合约

分身合约（CrossShardBase.sol）通过构造函数中的数学自鉴权彻底消灭伪造增发攻击面：若部署坐标不是根分片，合约总供应量强制为零，且不对外暴露任何铸币接口。唯一的资金来源是由共识层验证后的系统级跨分片转账调用，攻击者即使控制私钥也无法在分身合约上凭空增发。

### 8.5 Gas 确定性预扣

跨分片操作采用编译期确定的 Gas 定价：跨分片转账固定消耗 30,000 Gas，跨分片存储按数据长度线性计价。子调用失败时，快照栈无损回滚 Gas 和跨分片操作记录，保证 100% 确定性零异常终局——跨分片操作要么全部成功，要么 Gas 完整退还，不存在"半执行"状态。

## 9. 智能合约与 EVM 兼容性

### 9.1 执行引擎

Shardora 内嵌 **evmone** EVM 解释器，提供完整的以太坊兼容性。支持 Solidity 全版本、ERC-20/ERC-721/ERC-1155 标准代币、CREATE/CREATE2 合约部署、REVERT 错误回滚、EIP-155 重放保护、EIP-1559 Type 2 交易格式以及后量子签名（OQS ML-DSA-44）。

### 9.2 Gas 模型

系统 Gas 模型兼容 EIP-2028 和 EIP-2200 规范。普通转账消耗 21,000 Gas，合约创建 53,000 Gas 加 Calldata 费用，SSTORE 新存储槽 20,000 Gas，Calldata 非零字节 16 Gas、零字节 4 Gas，与以太坊主网保持一致，现有以太坊工具链无需修改即可使用。

### 9.3 Gas 预充与退还

用户在调用合约前预存 Gas，合约执行后扣除实际消耗，未使用部分退还。这一机制防止 Out-of-Gas 死账问题，同时支持合约开发者代用户支付 Gas（元交易模式）。

### 9.4 合约共置原子性

同一部署者通过 CREATE2 将 AMM 合约与关联代币合约部署到同一执行池，池内调用在单个共识轮次内完成，与以太坊单链的原子性完全等价，无需任何跨分片协调逻辑，也无需开发者编写补偿事务。

### 10.4 四维选举权重（FTS）

节点被选入委员会的概率由四个维度乘积决定：质押权重（PoS 安全保证）、信用权重（历史诚实激励）、区域权重（地理分散性）、任期反向权重（成员流动性）。四维乘积映射到 100–10000 的综合分值，VSS 随机数驱动的 FTS 按此分值进行加权随机选择，保证选举的公平性与不可预测性。

### 10.5 质押机制

最低质押门槛为 8 SHD。质押数据持久化存储，节点重启后自动恢复，无需重新操作。无白名单机制，任何人质押后提交加入选举交易即可参与。赎回质押需满足锁定期约束，防止节点提取质押后逃避惩罚。

## 11. 安全分析

### 11.1 共识安全性

**定理（安全性与活性）**：在 Fast-HotStuff 协议下，若任意时刻诚实节点数 n > 2f（f 为拜占庭节点数），则系统满足一致性与活性。

安全性依赖于 BFT 的经典论证：任何有效 QC 需要 t = ⌈2n/3⌉ 个签名；两个冲突 QC 的签名集合必须重叠至少 n/3 个节点；若诚实节点占比超过 2/3，交集中必有诚实节点，而诚实节点不会在同一视图下为冲突区块双重签名，因此冲突 QC 不可能同时存在。

### 11.2 DKG 安全性

基于 Feldman VSS 的 DKG 协议在 f < n/3 拜占庭节点假设下满足三条安全性质：**正确性**——所有诚实节点的份额来自同一多项式；**保密性**——攻击者无法从少于 t 个份额中恢复私钥；**可验证性**——Feldman 承诺使任何错误份额可被公开检测和排除。

### 11.3 跨分片最终一致性

**定理（强最终一致性）**：基于阿贝尔群结构的跨分片转账协议满足强最终一致性（SEC）：若两个节点接收到相同的消息集合，无论顺序如何，最终状态一定相同。

证明：令 B 为初始余额，{Δ₁, Δ₂, ..., Δₙ} 为已确认的转账增量集合。整数加法的交换律和结合律保证：无论消息到达顺序如何，最终状态均等于 B + ΣΔᵢ。有效性约束通过 GBP 高度单调性和唯一哈希在消息层面强制，防止无限透支。

### 11.4 Feistel 地址安全性

**定理（双射不可伪造性）**：4 轮 Feistel 置换网络构造的地址派生函数是 Z₂¹⁶⁰ 上的双射，在计算性安全假设下攻击者无法找到使不同本体地址产生相同分身地址的碰撞。共识层的逆映射断言在 C++ Host 层执行，无法被合约代码绕过。

### 11.5 攻击面总结

| 攻击类型 | 防护机制 | 保证强度 |
|---------|---------|---------|
| 51% 攻击 | BFT 共识（需 >2/3 控制委员会） | 密码学证明 |
| 双花攻击 | Nonce 单调性 + BFT 不可逆终局 | 协议保证 |

## 16. 结论

Shardora 通过五层技术创新的协同设计，在理论和工程实践中同时突破区块链不可能三角。

**密码学层**：BLS 门限签名将委员会投票的验证复杂度从 O(n²) 降至 O(1)，使千人委员会在 2 秒内达成共识成为可能，这是所有上层创新的基础。

**共识层**：Fast-HotStuff 两阶段流水线配合 EVS 将确认延迟控制在 1 秒量级，即使在 1024 个副本规模下仍保持亚秒级视图切换，解决了大规模 BFT 网络的性能退化问题。

**工程层**：等待分片双委员会机制使换届过程完全透明，业务无感知，消灭了传统 DKG 方案中不可避免的换届停机窗口，在五年内证明了这一工程挑战是可以解决的。

**数学层**：阿贝尔群可交换性使跨分片资产转移无需分布式锁，结合 Feistel 双射地址派生，从数学层面杜绝了跨分片伪造增发攻击，为多分片系统中智能合约的安全执行提供了坚实基础。

**经济层**：FTS 四维权重配合分代分片差异激励，在去中心化、安全激励和系统活力之间取得精细平衡，避免了质押经济中常见的头部节点垄断和成员固化问题。

以太坊用七年证明执行分片"理论上可行、工程上极难"。Shardora 以 25 万行经过国际顶级期刊严格评审的生产级代码证明：它**已经是现实**。
